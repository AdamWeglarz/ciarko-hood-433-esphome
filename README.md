# Ciarko SU Mini cooker hood → Home Assistant (ESP32 + 433 MHz)

Control a **Ciarko SU Mini** cooker hood from Home Assistant by making an ESP32 transmit
exactly the same 433 MHz frames as the original **XY8011-RF** remote. The ESP32 acts as a
second remote, so the original remote and the hood's own gesture control keep working.
The same board also runs as a **Bluetooth proxy** for Home Assistant, and its optional
433 MHz receiver can **learn your remote** and generate the button config for you.

The hood has no Wi-Fi, no open API and no documented RF protocol. This repo documents
the protocol, how to capture it (with the ESP itself or an RFLink gateway) and the
ESPHome config that drives the hood.

```
Home Assistant ──(ESPHome API, Wi-Fi)──► ESP32 ──GPIO26──► SYN115 ──433.92 MHz──► hood
                                          │ ▲
                                          │ └──GPIO27── SYN480R ◄── original remote (learning)
                                          └──────────── BLE proxy ──────────► BT devices
```

### Wiring

| Module | Module pin | ESP32 pin | Notes |
|---|---|---|---|
| SYN115 (TX) | VCC | 3V3 | **3.3 V only** – the module is rated for max. 3.6 V |
| SYN115 (TX) | DAT | GPIO26 | `remote_transmitter` |
| SYN115 (TX) | GND | GND | |
| SYN480R (RX) | VCC | 3V3 | At 3.3 V the DAT output is safe for the ESP32 |
| SYN480R (RX) | DAT | GPIO27 | `remote_receiver` (learning) |
| SYN480R (RX) | GND | GND | |

- Do not use CLK, D0–D3 and CMD – they are wired to the SPI flash.
- Solder 17.3 cm of wire to each module's ANT pad and keep the antennas a few cm apart.
- Mount the board so the PCB antenna end does not sit on the hood's metal body.

## Installation

1. Flash ESPHome over USB from Chrome/Edge at <https://web.esphome.io> (*Prepare for first use*).
   If it shows "Failed to connect", hold **BOOT** until the upload starts.
2. Adopt the device in the **ESPHome Device Builder** add-on in Home Assistant.
3. Copy `esphome/ciarko-hood.yaml` **and** `esphome/hood-codes.yaml` into the ESPHome
   config folder, fill in `secrets.yaml` from `secrets.yaml.example` and install wirelessly.
   - `framework: esp-idf` is required: with Arduino there is not enough RAM for the BLE proxy.
   - Do not add `web_server:` – it also runs out of RAM together with the BLE proxy.
4. Accept the new ESPHome device in *Settings → Devices & services*. You get seven buttons:
   Light, Fan +, Fan −, Left, Right, Timer, Timer (long press).

The shipped `hood-codes.yaml` contains the codes of the author's remote. If the hood does
not react, learn your own remote (next section).

**Toggle bit:** if the hood reacts only to every second press, it still remembers the
toggle bit from the original remote. Press once more and the ESP and hood are in sync.
The toggle state is not stored across ESP reboots, so the first press after a reboot can
be ignored.

## Learning your remote with the ESP

The firmware decodes 433 MHz frames on the ESP itself. The SYN480R outputs constant noise
when nothing transmits (~100 fragments per second), so `dump: raw` would flood the log and
the API. Instead, an `on_raw` lambda keeps only frames that look like the hood protocol
(PWM bits + sync HIGH) and logs one line per frame:

```
[08:10:27.958][I][hood:073]: HOOD code=101000010000100100011000100000110010 m1=755 s1=252 m0=266 s0=758 sync=1655
```

`m1/s1` = HIGH/LOW of a `1` bit, `m0/s0` = HIGH/LOW of a `0` bit, `sync` = sync HIGH, all in µs.

1. Flash `ciarko-hood.yaml` with the receiver connected.
2. Start the learner and press **every key 2–3 times, in the order given by `--keys`**,
   then press Ctrl+C:

   ```bash
   esphome logs esphome/ciarko-hood.yaml | \
     python3 tools/learn_remote.py --keys "Light,Fan +,Fan -,Left,Right,Timer" \
       --hold "Timer:70" -o esphome/hood-codes.yaml
   ```

   It also works on a saved log: `python3 tools/learn_remote.py esp.log --keys "Light"`.
3. Install the firmware again. The new codes and timing are compiled in.

What the learner does:

- groups frames into key presses (frames less than 0.4 s apart = one press);
- takes the most common full-length code of each press;
- finds the **toggle bit** as the bit that differs between consecutive presses of one key
  (falls back to bit 33 if every key was pressed only once) and builds both variants of
  each code;
- maps the keys, in order of first appearance, to the `--keys` names;
- writes the median measured pulse widths as `substitutions` for the sender script.
  The sync LOW cannot be measured (it is longer than the receiver's `idle`) and is fixed
  at 4680 µs.

Example output on the real remote (`captures/05_rflink_vs_esp_receiver.txt`):

```
37 frames, 7 presses, 36 bits, toggle bit 33
  Light        101000010000100100011000100000110010 / 101000010000100100011000100000111010
  timing mark_one=760 space_one=250 mark_zero=260 space_zero=760 sync_mark=1640 sync_space=4680
```

## The protocol

- Modulation: plain OOK/ASK at 433.92 MHz, no sub-carrier.
- Bit encoding (PWM), period ≈ 1 ms:
  - `1` = long HIGH, short LOW (≈ 750 / 250 µs)
  - `0` = short HIGH, long LOW (≈ 250 / 750 µs)
- Frame: **36 data bits followed by a sync**: HIGH ≈ 1640 µs, LOW ≈ 4680 µs.
- One key press is a burst of ~6 frames sent **back to back**. The sync of one frame
  runs straight into the first bit of the next one, with no pause.

```
 ┌~750┐250 ┌250┐ ~750   ...36 bits...  ┌──~1640──┐     ~4680      ┌~750┐ ...next frame
─┘    └─────┘   └──────               ─┘         └───────────────┘    └──
     bit "1"     bit "0"                       sync (trailing)
```

**Receivers disagree by ~90 µs.** The same signal was measured with two receivers at the
same time (`captures/05_rflink_vs_esp_receiver.txt`):

| Source → receiver | `1` HIGH/LOW | `0` HIGH/LOW | sync HIGH / LOW |
|---|---|---|---|
| remote → RFLink | 661 / 152 | 152 / 661 | 1530 / 4590 |
| ESP → RFLink | 660 / 149 | 149 / 660 | 1530 / 4590 |
| remote → ESP receiver | ~752 / 255 | ~262 / 762 | ~1645 / – |
| ESP → ESP receiver | 762 / 227 | 252 / 737 | 1632 / – |

Each receiver sees the remote and the ESP as practically identical. Between receivers there
is a constant offset: RFLink reports every pulse ~90 µs shorter. The ESP receiver measures
the ESP's own output (programmed 750/240) within ~15 µs, so its values are close to what is
really on air, and those are the numbers used above. When you compare captures, compare
them **on the same receiver**.

### Codes

| Key | Code, toggle bit = 1 | Code, toggle bit = 0 |
|---|---|---|
| Light | `101000010000100100011000100000111010` | `101000010000100100011000100000110010` |
| Fan + | `101000010000100100010001100010101010` | `101000010000100100010001100010100010` |
| Fan − | `101000010000100100001011100101001010` | `101000010000100100001011100101000010` |
| Left | `101000010000100101010000010010111010` | `101000010000100101010000010010110010` |
| Right | `101000010000100111111101111001101010` | `101000010000100111111101111001100010` |
| Timer | `101000010000100111111110100110011010` | `101000010000100111111110100110010010` |

- The first 16 bits (`1010000100001001`) are the same for every key. They are either an ID
  of this remote or a fixed header of all XY8011-RF remotes. With only one remote captured,
  it is impossible to tell. If yours differ, learn your remote.
- Bit 33 (counted from 1) is a **toggle bit**: it flips with every key press, so the hood
  can tell a new press from a repeated frame. The other 16 command bits differ per key and
  do not look like a simple key number. The same key always produces the same code, so
  this is not a rolling code.
- "Timer (long press)" is the Timer code repeated 70 times (~2.5 s) to emulate holding
  the Timer key on the remote.

## Capturing with RFLink instead of the ESP

If you have an RFLink gateway, it works as a reference receiver too
(`tools/rflink_sniff.py` + `tools/decode_pulses.py`). Stop any program that owns the
serial port (Domoticz, Home Assistant RFLink integration) first:

```bash
python3 tools/rflink_sniff.py 60 /dev/ttyACM0 > remote.txt   # press the keys meanwhile
python3 tools/decode_pulses.py remote.txt
```

What the remote looks like there (`captures/01_remote_light.txt`):

```
20;3D;DEBUG;Pulses=217;Pulses(uSec)=720,150,150,660,150,660,...,660,150,150,660,1530,4590,660,150,...
```

```
07:02:48 pulses=217 long~659 short~152 syncs=[(1530, 4590), (1530, 4590)]
    36 101000010000100100011000100000110010
    36 101000010000100100011000100000110010
```

- Bits are 660/150 µs, sync 1530/4590 µs. RFLink reads every pulse **~90 µs short**
  (see the receiver table above), so add ~90 µs to each value before you put it into
  `hood-codes.yaml`: 750/240, sync 1620/4680.
- A key press is one long train (217 pulses = data + sync, repeated, no gaps). RFLink
  splits it into packets of up to ~217 pulses; a packet ending in `6990` is the end of
  the burst.
- The first frame of a train is often missing 1–2 bits (receiver settling), so use
  the 36-bit frames.
- The ESP's output looks the same on RFLink (`captures/04_esp_final_continuous.txt`):
  one continuous train, 660/150 µs, trailing sync.

## Implementation notes

The hood only accepts frames that look exactly like the remote's burst, and that is not
what `remote_transmitter.transmit_rc_switch_raw` + `repeat` produce:

| | Original remote | `rc_switch` + `repeat` |
|---|---|---|
| Order | data → sync → data → sync … | sync → data, sync → data … |
| Between frames | nothing, continuous stream | gap > 7 ms after every frame |

So the firmware builds the whole burst in one `RemoteTransmitData` buffer and sends it
with a single `transmit()` call:

```cpp
for (int r = 0; r < times; r++) {
  for (char c : code) {
    if (c == '1') { d->mark(${mark_one}); d->space(${space_one}); }
    else          { d->mark(${mark_zero}); d->space(${space_zero}); }
  }
  d->mark(${sync_mark});    // trailing sync HIGH
  d->space(${sync_space});  // sync LOW, runs into the next frame
}
call.perform();
```

The script also flips the toggle bit and picks the matching code, so every button is a
single `script.execute` with both codes and the frame count.

Do not judge transmission by the ESPHome log alone: a button press does not necessarily
show up there. Check what is on air with the ESP receiver or RFLink.

## Troubleshooting

| Symptom | Check |
|---|---|
| Hood reacts to every second press | Toggle bit out of sync with the remote – press once more |
| Nothing at all | Learn the remote; check that bits, timing, sync position and gaps match on the **same** receiver |
| No `HOOD` lines when pressing the remote | Receiver wiring/antenna; press closer to the ESP |
| ESP log shows no button press | Not proof that nothing is sent – check with a receiver |
| API disconnects, "took a long time" warnings | Do not use `dump: raw` on the SYN480R – its noise floods the log |
| BLE proxy missing / crashes | Use `esp-idf`, no `web_server` |
| Short range | 17.3 cm antenna on the SYN115, board away from the metal hood body |
